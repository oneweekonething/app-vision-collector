# 微信采集攻略

适用于用户授权的群聊/单聊消息。使用 [调用者工作流](caller-workflow.md)，
由调用者自身看图导航和提取，不需要模型 API。

## 导航

start 使用 `--app wechat --target "群名"`；task 写明完整 App、群名和历史范围。
先 observe 看聊天列表，找到完全匹配目标再提交 Tap；找不到可打开搜索框，
确认焦点后用 Type 搜索（中文需要 ADBKeyBoard）。群名与搜索结果要看图核验。
用户也可手动定位，调用者仍需 observe 确认群标题后 capture。

## 翻页

查更早历史用手指下滑：Swipe `start:[500,300],end:[500,700]`。
从历史位置向更新消息采集则反向滑动；朋友圈按信息流方向手指上滑。
每屏保留约 60% 重叠，record 返回新增统计后再翻页。停止条件见主工作流；
不能仅凭重复消息或零新增判断已到历史边界。

## 字段

| 字段 | 说明 |
|------|------|
| sender | 从可见昵称确定，机主绿色气泡写「我」；不可见时 null，不沿用猜测 |
| text | 可见正文；图片 `[图片]`、语音 `[语音 X秒]`、链接 `[链接: 标题]` |
| time_hint | 只记录可见时间；可按提示词日历换算明确的相对时间，不确定则 null |
| type | text/image/voice/video/link/sticker/system |

采集期间避免人与调用者同时操作手机。弹窗或错误页面先 Back 后重新看图；
不要点击发送、回复等控件，不要在消息编辑框使用 Type。
